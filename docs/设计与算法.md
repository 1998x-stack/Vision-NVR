# Vision NVR 系统设计、算法与成熟产品对比

## 1. 需求映射

| 需求 | v1 实现 | 限制 |
|---|---|---|
| 网页实时看摄像头 | 本地 MJPEG，画面叠加时间戳、标注运动矩形 | 单摄像头、低刷新率预览 |
| 只保存变化部分 | 检测运动事件才录像；视频 H.264 帧间压缩 | 不保存全时段、静止事件不可回溯 |
| 时间轴不同颜色 | 未录制灰色；轻微/中等/明显活动分别绿色/黄色/红色 | 仅运动强度，不证明有人或识别对象 |
| 网盘式录像归档 | 年月日文件夹、日期列表、缩略图、回放、下载 | 无云同步，默认仅本机可访问 |
| 超过一个月自动清理 | 默认 30 天、2 分钟周期检查、保留已保护片段 | 系统服务运行时才会执行清理 |
| 避免硬盘爆满 | 最大录像存储 20GB + 最低剩余空间 2GB 门槛 | 不是磁盘故障保护，无备份功能 |

## 2. 运动算法

MOG2 使用 Gaussian Mixture Model 表征背景。对每帧产生前景掩码 M(x,y,t)。后续操作：

- 只保留二值掩码值 255（剔除 MOG2 识别的影子灰值）。
- 形态学开运算（去噪）与膨胀（连通前景区域）。
- 寻找连通轮廓，丢弃过小的前景轮廓。
- 有效变化比率 `score = (∑有效前景轮廓像素面积)/(缩小后画面总像素) × 100%`。
- 默认要求 `score >= 0.7%` 且连续三帧成立。特殊情况下，突然亮度大幅跳变并伴随大面积前景，忽略此样本。
- 起始时需要 22 帧预热；误报、漏报仍然可能出现。

这比简单 `absdiff` 两帧之差更能适应背景缓慢变化，也比始终运行人形检测模型轻量。

## 3. 视频编码

即使只录运动事件，也必须存入浏览器可播放的压缩视频流，而不是分别写数千张 JPEG。H.264 的 I/P/B 帧（实现细节取决于编码器参数）通过运动估计和预测降低跨帧冗余。当前用 `-preset veryfast -crf 29 -g 16` 做 CPU/文件体积折中。`-movflags +faststart` 将 MP4 元信息前置，便于网页播放。

## 4. 时间线意义

v1 默认只保留 MOG2 判定的运动事件，其余时间没有录制。页面将未保存录像的时段标记灰色，但**不能断言这些时段一定没有发生任何事件**（遮挡、低光、误检、硬件断线均可能导致漏报）。

## 5. 现代 NVR 功能清单

| 类型 | 常见成熟功能 | v1 状态 |
|---|---|---|
| 接入 | 多摄像头、RTSP/ONVIF、设备离线告警 | 单路 USB 摄像头 |
| 录像 | 连续录制与事件录制并存、分级保留、断网补偿 | 仅本地运动录像 |
| 算法 | 人/宠物/车检测、跟踪、区域 ROI、遮罩 | MOG2 运动识别 |
| 搜索 | 全文/对象检索、运动热力图、连续时间轴 | 日期、颜色事件条 |
| 浏览 | 事件审阅、缩略图、导出、收藏 | 支持主要基本操作 |
| 管理 | 用户权限、双因素、审计、备份与远程访问 | 本机操作，不支持公网 |
| 存储 | 分层保留、独立硬盘、多级限额 | 30 天 + 总量上限 + 保留空间 |
| 运维 | watchdog、硬件监控、异常推送、升级迁移 | systemd 用户服务、健康端点 |
